# 반복주기 수정 다음예정일 재계산

## 문제

- Task 수정에서 반복 주기만 바꿔도 기존 `nextDueAt`이 유지됐다.
- 서비스 핵심 규칙은 완료 날짜 기준 반복이므로, 최근 완료 이력이 있는 Task는 새 반복 주기를 최근 완료일 기준으로 다시 반영해야 한다.

## 결정

- 반복 주기 변경 시 `lastCompletedAt`이 있으면 최근 완료일의 KST 날짜에 새 반복 주기를 더해 `nextDueAt`을 재계산한다.
- 완료 이력이 없으면 첫 예정일 규칙을 유지해 `startDate`를 `nextDueAt`으로 둔다.
- `startDate`가 실제로 변경된 경우에는 기존처럼 시작일 00:00으로 `nextDueAt`을 재설정한다.

## 작업 내용

- `Task.update()`에서 반복 주기 변경과 시작일 변경을 분리해 감지하도록 변경했다.
- 반복 주기만 변경된 경우 최근 완료일 우선, 시작일 fallback 기준으로 다음 예정일을 재계산하게 했다.
- 수정 모달처럼 기존 시작일이 함께 전달되는 요청에서도 시작일 값이 같으면 최근 완료일 기준 재계산이 적용되게 했다.

## 테스트 방법

- 홈 화면에서 이미 완료 이력이 있는 Task의 수정 모달로 진입한다.
- 반복 주기를 `7`에서 `3`처럼 다른 값으로 변경하고 저장한다.
- Task 목록 또는 상세 화면의 다음 예정일이 최근 완료일 + 3일로 바뀌는지 확인한다.
- 완료 이력이 없는 Task는 반복 주기를 바꿔도 첫 다음 예정일이 시작일로 유지되는지 확인한다.
- 시작일을 실제로 다른 날짜로 바꾼 경우 다음 예정일이 변경한 시작일로 재설정되는지 확인한다.
