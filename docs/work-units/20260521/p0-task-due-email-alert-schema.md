# 작업 단위: p0-task-due-email-alert-schema

## 문제
- 매일 작업 마감 이메일 알림 기능을 위해 사용자별 발송 스케줄, 다중 수신 이메일, 일자별 1회 발송 추적을 담는 스키마 기반이 필요하다.
- 기존 스키마에는 해당 상태를 명확히 표현할 구조가 없어 스케줄러/중복방지 규칙을 안전하게 강제하기 어렵다.

## 결정
- 하나의 마이그레이션(`V7`)에서 아래 3개 스키마 블록을 함께 생성한다.
1. `task_due_email_alert_settings`: 사용자별 알림 활성화, 발송 시각, 타임존, 마지막 발송 로컬 날짜 관리
2. `task_due_email_alert_recipients`: 사용자별 다중 수신 이메일 저장
3. `task_due_email_alert_delivery_logs`: 사용자+로컬날짜 단위 발송 결과/재시도 메타데이터 기록

## 트레이드오프
- 장점: 설정/수신자/발송상태 경계를 분명히 분리해 스케줄러 로직의 신뢰도를 높일 수 있다.
- 단점: 초기 스키마 복잡도가 늘어나지만, 이후 임시 상태 처리로 인한 운영 리스크를 줄일 수 있다.

## 구현 요약
- `apps/api/src/main/resources/db/migration/V7__create_task_due_email_alerts.sql` 추가
- `V7`에 설정 테이블, 수신자 테이블, 일일 발송 로그 테이블을 통합 생성하도록 반영

## 테스트 방법
- 마이그레이션 실행 후 3개 테이블과 기본값/제약조건이 기대대로 생성되는지 확인한다.
- 기존 사용자 기준으로 `task_due_email_alert_settings` 기본 행이 백필되는지 확인한다.
- 동일 사용자에서 이메일 대소문자만 다른 중복 입력이 차단되는지 확인한다.
- 동일 사용자/로컬날짜로 `task_due_email_alert_delivery_logs` 중복 삽입이 차단되는지 확인한다.

## 관련 테스트
- 자동화 테스트 추가 없음 (스키마 전용 변경)

## 한 줄 요약
- 사용자별 작업 마감 이메일 알림을 위한 설정/수신자/일일 중복방지 로그 스키마를 `V7` 단일 마이그레이션으로 구축했다.
