# 작업 단위: 알림 설정 요청 연결 타입

## 문제
- 알림 설정 화면을 만들기 전에 프론트에서 백엔드 알림 설정 API를 호출할 연결층이 필요하다.
- 설정 조회/수정과 수신 이메일 목록/추가/삭제 요청에 사용할 타입이 아직 없다.

## 결정
- 기존 프론트 구조와 맞춰 `apiClient`를 사용하는 알림 설정 API 파일을 추가한다.
- 백엔드 응답/요청 형태는 별도 타입 파일로 분리한다.
- 이번 단계에서는 화면 구현 없이 설정/수신자 API 연결만 추가한다.

## 트레이드오프
- 장점: 다음 화면 작업에서 API 호출 로직을 다시 만들지 않고 바로 사용할 수 있다.
- 장점: 화면 구현과 API 타입 작업을 분리해 변경 범위를 작게 유지한다.
- 단점: 아직 화면에서 사용하지 않으므로 실제 사용자 동작 검증은 다음 단계에서 진행해야 한다.

## 구현 요약
- 알림 설정 응답/수정 요청 타입 추가
- 수신 이메일 응답/추가 요청 타입 추가
- 알림 설정 조회/수정 API 함수 추가
- 수신 이메일 목록/추가/삭제 API 함수 추가
- 공용 타입 export에 알림 설정 타입 추가

## 테스트 방법
- 프론트 타입 체크로 신규 타입과 API client import/export가 깨지지 않는지 확인한다.

## 관련 테스트
- 자동화 테스트 없음

## 한 줄 요약
- 알림 설정 화면에서 사용할 프론트 API 연결층과 타입을 추가했다.
