# 작업 단위: 알림 설정 페이지 진입점

## 문제
- 알림 설정 API 연결층은 있지만 사용자가 접근할 수 있는 전용 화면이 아직 없다.
- 홈 화면에서 알림 설정 페이지로 넘어갈 수 있는 라우트와 네비게이션 진입점이 필요하다.

## 결정
- 전용 알림 설정 페이지 경로는 `/alerts`로 둔다.
- 상단 네비게이션에 `알림 설정` 버튼을 추가한다.
- 이번 단계에서는 수정 폼 없이 현재 알림 설정과 수신 이메일 목록을 조회해 보여주는 읽기 화면까지만 구현한다.

## 트레이드오프
- 장점: 홈 화면을 복잡하게 만들지 않고 알림 설정 기능을 별도 영역으로 확장할 수 있다.
- 장점: 다음 단계에서 발송 설정 저장 UI와 수신 이메일 관리 UI를 작게 이어 붙일 수 있다.
- 단점: 아직 알림 설정 수정이나 수신 이메일 추가/삭제는 화면에서 직접 할 수 없다.

## 구현 요약
- `/alerts` 라우트 추가
- 상단 네비게이션에 알림 설정 진입 버튼 추가
- 알림 설정 페이지 컴포넌트 추가
- 설정 조회, 수신 이메일 조회, 로딩, 에러 재시도, 빈 상태 표시 추가
- 알림 설정 페이지 스타일과 모바일 반응형 처리 추가

## 테스트 방법
- 프론트 타입 체크로 신규 라우트/컴포넌트/API 호출 연결이 빌드 가능한지 확인한다.
- 로컬 웹 서버를 띄운 뒤 로그인 상태에서 상단 `알림 설정` 버튼으로 `/alerts` 이동을 확인한다.

## 관련 테스트
- 자동화 테스트 없음

## 한 줄 요약
- 전용 알림 설정 페이지와 홈에서 이동 가능한 네비게이션 진입점을 추가했다.
