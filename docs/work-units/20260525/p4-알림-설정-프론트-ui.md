# 작업 단위: 알림 설정 프론트 UI

## 작업 내용
- 알림 설정 응답/수정 요청 타입 추가
- 수신 이메일 응답/추가 요청 타입 추가
- 알림 설정 조회/수정 API 함수 추가
- 수신 이메일 목록/추가/삭제 API 함수 추가
- 공용 타입 export에 알림 설정 타입 추가
- `/alerts` 라우트 추가
- 상단 네비게이션에 알림 설정 진입 버튼 추가
- 알림 설정 페이지 컴포넌트 추가
- 조회 화면에 사용 여부, 발송 시간, 최근 발송일, 수신 이메일 목록 함께 표시
- 별도 발송 상태 표시 제거, 사용 여부는 조회 요약과 변경 모달에서만 표시
- `변경` 버튼을 누르면 모달에서 발송 설정과 수신 이메일 통합 편집
- 알림 사용 여부 토글 UI 추가
- 발송 시간 입력 UI 추가
- 타임존 입력과 추천 목록 추가
- 설정 변경/취소/저장 흐름 추가
- 수신 이메일 입력 폼 추가
- 로그인 아이디 이메일이 아직 등록되지 않았을 때만 입력칸 기본값으로 표시
- 수신 이메일 추가/삭제 요청 연결
- 최대 수신 이메일 개수 도달 시 입력/추가 버튼 비활성화
- 최대 수신 이메일 개수 도달 시 입력칸 바로 위에 빨간 경고 메시지 표시
- 저장/추가/삭제 성공 메시지 표시
- 중복, 최대 개수 초과, API 실패 에러 메시지 표시
- 알림 설정 페이지 스타일과 모바일 반응형 처리 추가
- 프론트 work unit 작성 기준을 작업 규칙에 반영

## 테스트 방법
- 프론트 타입 체크로 신규 타입, API client, 라우트, 컴포넌트 연결이 빌드 가능한지 확인한다.
- 로컬 API와 웹 서버를 띄운 뒤 로그인한다.
- 상단 `알림 설정` 버튼으로 `/alerts` 이동을 확인한다.
- 조회 화면에 사용 여부, 발송 시간, 최근 발송일, 수신 이메일 목록이 함께 표시되는지 확인한다.
- `변경`을 눌렀을 때 알림 설정 변경 모달이 표시되는지 확인한다.
- 모달에 불필요한 설명 문구 없이 발송 설정 편집 폼과 수신 이메일 입력/삭제 UI가 표시되는지 확인한다.
- 로그인 아이디 이메일이 아직 수신 목록에 없으면 이메일 주소 입력칸에 기본값으로 표시되는지 확인한다.
- 로그인 아이디 이메일을 등록한 뒤에는 이메일 주소 입력칸이 비어 있는지 확인한다.
- 값을 변경하고 `발송 설정 저장`을 눌러 성공 메시지와 요약 값이 갱신되는지 확인한다.
- 새 이메일을 입력하고 `수신 이메일 추가`를 눌러 목록에 즉시 추가되는지 확인한다.
- 이미 등록된 이메일을 다시 입력하면 중복 에러가 표시되는지 확인한다.
- 목록의 `삭제` 버튼을 눌러 해당 이메일이 목록에서 제거되는지 확인한다.
- 수신 이메일을 최대 개수까지 등록하면 입력창과 추가 버튼이 비활성화되고 입력칸 바로 위에 빨간 경고 메시지가 표시되는지 확인한다.
- 모달 닫기 버튼이나 `닫기`를 누르면 모달이 닫히는지 확인한다.
- 잘못된 타임존 값을 입력하면 백엔드 에러 메시지가 표시되는지 확인한다.
