# 작업 단위: 작업 마감 이메일 자동 발송 스케줄러와 테스트

## 문제
- 작업 마감 이메일 알림은 사용자가 설정한 시각과 타임존 기준으로 자동 발송되어야 한다.
- 매번 모든 활성 알림 설정을 앱에서 계산하기보다, 발송 예정 시각이 된 설정만 조회하는 구조가 필요하다.
- `next_send_at` 기반 자동 발송은 시간 계산, due 조회, 발송 로그, 재시도 흐름이 함께 맞아야 안정적으로 동작한다.
- 설정 수정 시 다음 발송 예정 시각이 갱신되는지도 회귀 없이 검증해야 한다.

## 결정
- 알림 설정에 `next_send_at`을 저장한다.
- 스케줄러는 `next_send_at`이 현재 시각 이전인 활성 설정만 조회한다.
- 발송 성공, 스킵, 실패 후에는 다음 발송 예정 시각을 다음 날로 갱신한다.
- 수신자 없음 또는 발송 대상 작업 0건은 메일을 보내지 않고 `SKIPPED` 로그로 기록한다.
- 메일 발송 실패는 같은 실행 안에서 최대 2회까지 시도하고 실패 로그를 남긴다.
- 다음 발송 예정 시각 계산은 별도 단위 테스트로 검증한다.
- 자동 발송 서비스는 수신자 없음, 발송 대상 없음, 성공, 실패 재시도, 중복 로그 스킵 흐름을 mock 기반 단위 테스트로 검증한다.
- repository 테스트에서는 `next_send_at`이 지난 활성 설정만 조회되는지 PostgreSQL 기반 JPA 테스트로 검증한다.

## 트레이드오프
- 장점: 사용자 수가 늘어도 매번 모든 활성 설정을 계산하지 않고, DB 인덱스로 발송 대상만 조회할 수 있다.
- 장점: 자동 발송의 핵심 분기와 DB 조회 조건을 빠르게 검증할 수 있다.
- 단점: 설정 변경과 발송 처리 시 `next_send_at`을 정확히 갱신해야 한다.
- 단점: 실제 SMTP 발송과 스케줄러 시간 경과 자체는 단위 테스트가 아니라 Mailpit 수동 검증으로 보완해야 한다.

## 구현 요약
- `next_send_at` 컬럼과 인덱스 추가
- 알림 설정 엔티티에 다음 발송 예정 시각 필드 추가
- 다음 발송 예정 시각 계산 컴포넌트 추가
- 알림 설정 수정 시 `next_send_at` 갱신
- `next_send_at <= now()` 대상 조회용 repository 메서드 추가
- 자동 발송 서비스와 스케줄러 추가
- 수신자 없음, 발송 대상 없음, 발송 성공, 발송 실패 로그 처리 추가
- 다음 발송 예정 시각 계산 테스트 추가
- 설정 수정 시 `next_send_at` 갱신 검증 추가
- 자동 발송 서비스 스킵/성공/실패 재시도 테스트 추가
- due 설정 조회 repository 테스트 추가

## 테스트 방법
- alert 패키지 테스트로 자동 발송 관련 신규 테스트를 확인한다.
- 전체 API 테스트로 기존 기능 회귀 여부를 확인한다.
- 실제 SMTP 수신 결과는 Mailpit 수동 검증으로 보완한다.
