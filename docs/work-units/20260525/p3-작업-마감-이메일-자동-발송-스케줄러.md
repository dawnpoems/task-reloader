# 작업 단위: 작업 마감 이메일 자동 발송 스케줄러

## 문제
- 작업 마감 이메일 알림은 사용자가 설정한 시각과 타임존 기준으로 자동 발송되어야 한다.
- 매번 모든 활성 알림 설정을 앱에서 계산하기보다, 발송 예정 시각이 된 설정만 조회하는 구조가 필요하다.

## 결정
- 알림 설정에 `next_send_at`을 저장한다.
- 스케줄러는 `next_send_at`이 현재 시각 이전인 활성 설정만 조회한다.
- 발송 성공, 스킵, 실패 후에는 다음 발송 예정 시각을 다음 날로 갱신한다.
- 수신자 없음 또는 발송 대상 작업 0건은 메일을 보내지 않고 `SKIPPED` 로그로 기록한다.
- 메일 발송 실패는 같은 실행 안에서 최대 2회까지 시도하고 실패 로그를 남긴다.

## 트레이드오프
- 장점: 사용자 수가 늘어도 매번 모든 활성 설정을 계산하지 않고, DB 인덱스로 발송 대상만 조회할 수 있다.
- 단점: 설정 변경과 발송 처리 시 `next_send_at`을 정확히 갱신해야 한다.

## 구현 요약
- `next_send_at` 컬럼과 인덱스 추가
- 알림 설정 엔티티에 다음 발송 예정 시각 필드 추가
- 다음 발송 예정 시각 계산 컴포넌트 추가
- 알림 설정 수정 시 `next_send_at` 갱신
- `next_send_at <= now()` 대상 조회용 repository 메서드 추가
- 자동 발송 서비스와 스케줄러 추가
- 수신자 없음, 발송 대상 없음, 발송 성공, 발송 실패 로그 처리 추가

## 테스트 방법
- 컴파일로 신규 마이그레이션 참조, 엔티티, repository, 스케줄러 서비스가 빌드 가능한지 확인한다.
- 이후 테스트 단계에서 다음 발송 시각 계산, due 설정 조회, 스킵/성공/실패 로그, 재시도 동작을 검증한다.

## 관련 테스트
- 자동화 테스트 추가 없음 (이번 단계는 구현 코드만 진행)
