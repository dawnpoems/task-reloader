# 작업 단위: p2-vite-6-4-2-security-upgrade

## 문제
- `apps/web`가 `vite@6.4.1`을 사용 중이어서 npm audit에서 Vite 보안 권고 2건(`GHSA-p9ff-h696-f583`, `GHSA-4w7w-66w2-5vf9`)이 탐지됐다.
- dev server 기반 취약점이므로 로컬/사내망 개발 환경에서도 패치 버전 반영이 필요했다.

## 취약점 상세
- `GHSA-p9ff-h696-f583` (High): Vite 개발 서버 WebSocket 경로를 통해 비인가 사용자가 임의 파일을 읽을 수 있는 취약점.
- `GHSA-4w7w-66w2-5vf9` (Moderate): optimized deps의 `.map` 처리 경로에서 path traversal이 가능해 파일 경로 이탈이 발생할 수 있는 취약점.
  - 쉽게 말해: 원래는 프로젝트 폴더 안 파일만 읽어야 하는데, 경로를 교묘하게 조작하면 상위 폴더 쪽 파일까지 접근할 여지가 있었다.
  - 영향 예시: 개발 서버를 외부에서 접근 가능한 상태로 띄웠다면, 민감 파일(`.env` 등) 노출 위험이 생길 수 있다.
- 영향 버전: `<= 6.4.1`
- 패치 버전: `6.4.2` 이상 (6.x 라인 기준)

## 결정
- `vite`를 major 업그레이드(7/8)가 아닌 패치 업그레이드 `^6.4.2`로 반영한다.
- lockfile도 함께 갱신해 실제 설치 버전을 `6.4.2`로 고정한다.

## 트레이드오프
- 장점: 변경 범위를 최소화하면서 Vite 관련 취약점을 즉시 해소할 수 있다.
- 단점: 최신 major 기능/개선은 즉시 가져가지 못하고, 7/8 전환은 별도 작업으로 남는다.

## 구현 요약
- `apps/web/package.json`의 `vite` 버전을 `^6.4.1 -> ^6.4.2`로 변경
- `apps/web/package-lock.json`에서 `node_modules/vite` 해시와 resolved URL을 `6.4.2` 기준으로 갱신
- 업그레이드 후 `npm audit` 재확인 시 Vite 취약점 항목 제거 확인

## 테스트 방법
- 변경된 테스트 코드는 없다.
- 웹앱 빌드(`npm run build`)가 통과하는지 확인해 번들링 회귀가 없는지 검증한다.
- `npm audit` 결과에서 Vite 항목이 사라졌는지 확인한다.

## 관련 테스트
- 자동화 테스트 추가 없음 (의존성 패치 반영 작업)

## 한 줄 요약
- `apps/web`의 Vite를 `6.4.2`로 패치 업그레이드해 보고된 Vite 취약점 탐지를 해소했다.
